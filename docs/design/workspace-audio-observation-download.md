The existing saved-recording library successfully uses a parent-owned prepared-file/download-button pattern; the live audio export now follows that source pattern.

The child retains its standalone link. Export also sends a File containing the exact dated metadata snapshot to the declared parent only when its origin matches the document referrer. The receiver applies the existing live frame/source/origin/session gate. Its helper accepts only an application/json File named audio-observation.json,1..16384bytes, matching recording name, schema, declared session, unverified executable-identity flag and bounded valid observation timestamp. Parsing reads the bounded immutable File once. No backend query, asset upload, PCM copy or runtime operation is added.

The parent prepares a Blob URL and shows Download audio observation with the recording name and timestamp. Download requires a separate normal workspace click. No message automatically downloads a file. A validated preparation acknowledgement is bound to the request/session/source/origin; only then does the child tell the user the workspace file is ready. This acknowledgement is not successful download or audio qualification.

Generation guards discard late reads after replacement, session change or disposal. New sessions clear the prior prepared file and revoke its URL. Explicit replacement revokes the old URL only after the new file is admitted. Failed preparation retains the prior dated download. Runtime stop does not revive execution controls; this metadata branch only prepares a file. Rebuilding controls and disposing the owner clear the helper.
