# Separate elapsed time from wall time

Source inspection of downstream BoxedWine platform/linux/platform.cpp found the default micro counter subtracting a startup gettimeofday wall-time value from later wall-time reads. KSystem::getMicroCounter feeds guest monotonic clock calls from this owner. The old Emscripten-specific alternative was disabled under __THIS_HANGS__ and multiplied millisecond emscripten_get_now by 1000000, which is not microseconds.

The Emscripten branch now records and reads emscripten_get_now multiplied by 1000. Selected local SDK4.0.14 libcore.js uses performance.timeOrigin+performance.now for pthread builds, providing a shared time-origin basis for main/worker reads. Both samples are converted to unsigned microseconds before subtraction. This is elapsed host performance time; it is not simulation ticks, pause-time exclusion or restored virtual time. Wall clock getSystemTimeAsMicroSeconds and the non-Emscripten native branch are unchanged. No GL4ES vendor source edited.

Native clock.c remains a distinct virtual-clock owner: per-tick frozen V, uptime/QPF/FILETIME declarations, read-budget micro-advance and clock state retained with restored native memory. WASM teloscontrol parks guest workers but does not implement that clock contract. Current kernel gettimeofday also reads Platform wall time directly rather than KSystem adjusted clock. No blanket freeze or clock-scaling behavior was introduced; native injection, coherent state/clock restore and deterministic replay remain open. This finding does not establish the cause of observed camera/labels/input/control issues.
