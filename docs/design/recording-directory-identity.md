# Associate receipts with their recording directory

The existing P4 recording owner now adds recording=request.name when creating the OPFS writer metadata. The storage owner supplies this field after request metadata, so a caller declaration cannot override the directory selected for the write. Each subsequent incomplete or finalized receipt retains that name. Runtime session/release/context declarations remain separate and unqualified. Existing files and receipts are not rewritten.

The library reads the finalized receipt before and after fetching game.webm using its existing stable-byte check. Both reads now reject a declared recording name that differs from the selected directory. The parent finalized-file receiver independently applies the same optional-name check while retaining complete/bytes/chunks/end-time admission. Legacy receipts without the field remain readable and are labeled as not declaring directory identity. This is a directory declaration, not a cryptographic media binding, proof of continuity, playback, audible content, exact game frames, full run or replay.
