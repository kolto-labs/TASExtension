## Safety/contract corrections

The former installer sequence activated a staged closure before committing its durable profile lock. The diagram now separates preflight admission, durable desired-lock publication with activation pending, safe-boundary activation and its outcome receipt. Text explicitly distinguishes installed/desired and admitted runtime closures, requires startup recovery of pending activation and retains the previous lock/fault receipt. Actual filesystem/game transaction atomicity is still an U20 fault-injection gate; this edit does not implement it.

Restore quiescence now keeps TAS supervisor admission/verification authoritative, using Core participant services without implying a second game owner. Browser catalog actions still hand off to a local manager; the site cannot mutate the native rig. The compact UI selectors' More placement is reconciled with the old permanent-top-row requirement, without upgrading native visual acceptance.

- U17 must inventory the real KPM bootstrap/readiness/ABI and native unload limits before binding the proposed facade.

- U20 must choose a maintained signed-update implementation and prove commit/activation/recovery on supported filesystems. Native activation failures are not a universal rollback guarantee.
- U21/U22 must select the catalog/authentication backend and implement real graph/search, publisher authorization and discussion. Static Worker hosting alone supplies none of these.
- The graph's reciprocal conflict/co-use semantics and recommendation sample thresholds remain implementation-contract decisions; author/source/environment labels and no-fabricated-activity rules are already required.
- Current runtime/evidence paragraphs contain older measured values and test cuts. Root must update them from its latest receipts; this review neither refreshed live state nor claims the pending physical UI/Routine acceptance completed.
