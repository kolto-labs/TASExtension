# Native HUD and controls — isolated implementation candidate

This implementation displays the runtime mode, tick and applied DirectInput state over the game. TAS mode keeps its watermark, including an Aurebesh TAS badge. `MODE TAS` describes the locked runtime mode; it does not certify base-game fidelity or replace a judge receipt. Detailed status is available through `hud.stats`.

The HUD uses an owned, non-activating layered Windows tool window. The SwapBuffers hook updates it on the harness stack. It does not paint into the game's GL framebuffer, change its GL state, allocate game GL objects, or consume GL errors. Frame-ring exports receive their labels in the output buffer, including repeated and blank frames. A restored state whose game view has not been redrawn is labelled accordingly. This design still needs live on/off comparisons for state, files, input timing, focus and messages; a separate surface alone does not establish neutrality.

To operate a recorded bundle with the shim:

```text
telos --config telos.toml control recording.holo --tick 420 \
  --branch-score edited.score --branch-out edited.holo
```

With the game focused, hold Ctrl+Alt and press:

- F8: play one tick of the recorded note.
- F9: strictly restore the previous recorded tick.
- F10: validate and play the prepared edited-score branch through the normal restore/record pipeline.
- F11: close the control session.

The single-step action refuses score directives such as a wait or relaunch rather than running an unbounded transition. Use normal score playback for those transitions. Branch playback closes the preview process first, then uses the existing checked branch pipeline; it is not a second concurrent game. It validates the score prefix and refuses an existing output path. A failed restore is reported rather than presented as a successful rewind.

The native `frame` command exports the latest captured BGRA buffer with explicit dimensions, format and SHA256. The Python backend verifies those bytes and returns PNG. It requires frame capture to have reached a gate and does not trigger a second GL readback. An output path must be new.

The hands-off backend now checks local process mappings for the pinned executable and exactly one executable dinput8 mapping with a Wine builtin marker before starting input. It records module paths and hashes, verifies mapped file identities, and rejects a missing builtin marker or known tool module. The marker is only an observation. Real startup requires an explicit `handsoff.runtime_pin` table before window activation or new input. Its exact fields are `schema_version = 1`, lowercase `sha256`, positive byte `size`, integer `pe_machine` (332 for i386, 34404 for AMD64, or 43620 for ARM64), and a `package` table containing nonempty `name`, `version`, and `architecture`. Package architecture can differ from PE machine for a WoW64 package. Obtain the expected identity independently; the backend never creates a pin from the currently loaded file.

The attestor compares the pin against bytes read from the retained mapped-file descriptor and parses the PE DLL machine. Missing pins, malformed headers and mismatched bytes, sizes or machines refuse real startup. A successful match records `builtin_identity = "matches_declared_runtime_pin"` with the complete supplied pin. Package fields remain caller declarations bound to that digest: `runtime_package_origin = "not_independently_verified"`. This slice does not query package databases or verify publisher signatures, and a matching declaration does not establish trusted package origin. Diagnostic `attest()` without a pin still reports `builtin_identity = "not_attested"`; dry-run mode dispatches no commands and needs no pin. Remote process namespaces are refused until attestation for that route exists. This is not proof that no other physical input occurred: evidence explicitly reports `exclusive_input: not_attested`. Hands-off still uses wall-score ticks and timeout-based sync frame observations, not observed engine ticks. Its external on-screen watermark and full input-provenance/video acceptance remain incomplete.

The Aurebesh badge comes from [Aurebesh Rodian by AurekFonts](https://github.com/AurekFonts/Aurebesh_Rodian), pinned at commit `e73d7bca778086b4d22d5f701539c2e9be930bbc`, under its MIT license. Font, license and hashes are retained in `native/shim/assets/aurebesh-rodian`; the checked-in bitmap is generated by `native/shim/tools/hud_badge.py`. Ordinary controls remain readable in Latin text.

No game was launched for this implementation. Passing source fixtures or a compiled DLL is not M5 completion. Remaining live gates include visual tick/input correspondence, repeated/blank/postrestore frames, tool-key isolation, focus/message neutrality, native state/files/input/core-journal equality with HUD and capture toggled, and hands-off playback/module/input/video evidence. Integration remains separate from the current M3 acceptance candidate.
